Remix Toolkit for Blender

Direct NVIDIA backend (P0)

The importer has two backends. The default direct backend runs NVIDIA's capture algorithms inside Blender using the pxr (OpenUSD) that ships with Blender. It does not start RTX Remix Toolkit, Omniverse Kit, StageCraft, an MCP server or any HTTP/REST service, and it writes no intermediate files. Only Blender's bundled pxr is used; pxr binaries are never mixed.

The old importer is preserved verbatim as rtx_remix_importer/legacy_import_core.py and remains the rollback path.

Layer state from the Toolkit workfile (P1)

Toolkit workfiles store per-project layer state in the root layer's customLayerData:

dictionary omni_layer = {
    dictionary locked = { bool "./capture.usda" = 1 }
    dictionary muteness = { bool "./baker.usda" = 1 }
}

The direct backend applies this state when a project opens:

  • omni_layer.muteness → Usd.Stage.MuteAndUnmuteLayers; muted sublayers no longer participate in composition.
  • omni_layer.locked → Sdf.Layer.SetPermissionToEdit(False); locked layers become read-only in memory.
  • The mod/replacement layer and the capture layer are deliberately protected: they are never muted by this code.
  • There is no mute/lock toggle UI and no drag-and-drop layer reordering yet.

Muting invalidates the Python handles of muted layers in some OpenUSD builds, so the backend reports muted layers by identifier. Metadata-locked layers are not rewritten when the capture sublayer is re-appended.

Backend switch and rollback

Resolution order:

  1. REMIX_IMPORT_BACKEND environment variable.
  2. scene["remix_import_backend"] custom property.
  3. direct (default).
ValueBehaviour
direct (default)NVIDIA algorithms in process; on an unexpected error the import is logged and retried with the legacy importer.
direct-onlyStrict direct backend; errors are raised and never fall back.
legacyOld importer only — use this to roll back instantly.
 
# strict direct backend
$env:REMIX_IMPORT_BACKEND = "direct-only"

# rollback to the previous importer
$env:REMIX_IMPORT_BACKEND = "legacy"

To roll back permanently, set the same value in the scene property or remove the blender_bridge / nvidia_core / compatibility packages and restore import_core.py from legacy_import_core.py. All changes are additive apart from the import_core.py rename, so git revert of the integration commit is enough.

Import semantics

  • The capture layer is locked in memory. Only the mod/replacement layer is an edit target; ProjectComposition.add_capture_sublayer() appends a capture as the weakest sublayer after removing any previous capture.
  • With the UI default Capture Scale = 0.01, the direct backend uses the capture's own metersPerUnit and upAxis (captures commonly author 0.01 and Y-up). Any other UI value is treated as an explicit override.
  • One Blender mesh datablock is shared by every instance of a prototype. Materials are linked per object (slot.link = 'OBJECT') so instances can differ without duplicating geometry.
  • Capture materials are resolved through the direct material:binding, composed bindings, then prototype and mesh-child fallbacks. Invalid targets (for example a stale /RootNode/Looks/... path) are rejected.

The suite covers the Kit adapters, prim utilities, capture helpers, composition/locking, geometry (n-gons, left-handed winding, primvar indices), capture immutability, backend selection/fallback and real Blender imports of both capture.usda and full_project.usda.

Composition tests verify that omni_layer muteness hides muted sublayers, that metadata-locked sublayers become read-only, that saving a project writes only the mod layer, and that authoring into the locked capture raises. tests/blender/test_ui_operators.py drives the actual UI operators (remix.import_capture, remix.scan_capture_folder) end to end, including the scene-property backend switch and the direct-only error path. tests/unit/test_hide.py and TestHideMeshOperators cover hiding/restoring captured meshes: the mask is authored on the reference-owning instance prim, the capture file hash is unchanged, no assets/ output appears, and the composed geometry disappears and returns.

Not verified

  • No real game capture with textures was available; only the Toolkit fixture (two DDS files) was exercised.
  • Blender 4.0–4.4, Linux/Wine and non-ASCII Windows paths were not run.
  • Interactive UI clicking was not exercised; the operators are tested in --background.
  • In the test environment the Aperture Opaque node group could not be appended, so material conversion exercised the existing Principled BSDF fallback.
  • omni_layer muteness/locking is exercised on the Toolkit fixture. Projects that mute the capture or the mod authoring layer are not covered: those layers are protected and deliberately never muted, while the reference Toolkit may expose a different UI policy for them.
  • Light import delegates to the existing light_utils.py, which still warns about Y-up rotation.
  • The resulting mod has not been loaded in the RTX Remix runtime or a game.

Requirements and installation

Requirements

  • Windows (or Wine on Linux)
  • Blender 4.0 or newer (verified in background mode on 4.5.5 LTS and 5.1.2)
  • texconv from DirectXTex — only needed for the source install; it ships inside the release zip

From a release

  1. Download the latest release from github.com/hopelessnes5/blender-remix/releases
  2. In Blender: Edit > Preferences > Add-ons > Install..., pick rtx_remix_importer.zip
  3. Enable Remix Toolkit for Blender

From source

  1. Clone the repository
  2. Put texconv.exe into rtx_remix_importer/texconv/ (create the folder); texconv.exe is git-ignored, so it is not part of the clone
  3. Edit > Preferences > Add-ons > Install... and select the rtx_remix_importer folder (or copy it into scripts/addons/)
  4. Enable Remix Toolkit for Blender

If Blender ever refuses to pick up a code change, clear the bytecode cache with delete-py-cache-and-open-blender.ps1 in the repository root.

Usage

Import captures

  • Open the RTX Remix panel in the 3D viewport sidebar (N key)
  • Set Captures > Capture Folder to your game's capture folder
  • Import a single capture, or tick several and use Batch Import Selected

Project and sub-layers

  • RTX Remix Project > Remix Mod File — point at an existing mod.usda or create a new one
  • RTX Remix Project > Sublayers — pick the target sub-layer, or create a new one
  • The active target layer receives every export

Export meshes and lights

  1. Select an imported object as Export Settings > Target Mesh (the captured mesh whose hash has to be replaced). If you export an object that was imported from a capture, it is used automatically
  2. Import or create meshes / lights and place them in the scene
  3. Select them and press Export Selected Meshes/Lights

What gets written in the target layer:

over "RootNode"
{
    over "meshes"
    {
        over "mesh_<16HEX>" ( references = None )
        {
            def Xform "ref_<32HEX>" ( prepend references = @./assets/ingested/<mesh>.usda@ )
            {
                custom bool IsRemixRef = 1
                ... identity translate / rotateXYZ / scale ...
            }
        }
    }
}

The ingested asset referenced from there is a self-contained mesh asset:

def Xform "ReferenceTarget" ( kind = "group" )      # defaultPrim
{
    def Xform "XForms" ( kind = "group" )
    {
        def Mesh "<mesh>" ( prepend apiSchemas = ["MaterialBindingAPI"] )
        {
            rel material:binding = </ReferenceTarget/Looks/<mesh>__> (
                bindMaterialAs = "weakerThanDescendants"
            )
            uniform token subdivisionScheme = "none"
        }
    }
    def "Looks" { def Material "<mesh>__" { ... } }
}

Hide / restore captured meshes (no export)

  1. Select one or more imported capture meshes
  2. Press Hide Selected Meshes — the add-on only writes into the mod layer:
over "RootNode"
{
    over "instances"
    {
        over "inst_<16HEX>_<N>" ( references = None )
        {
        }
    }
}
  1. Press Restore Hidden Meshes with the same selection to remove the mask

No mesh, material or texture is exported. The capture layer is opened read-only and is never modified; hiding is refused if the prim already owns a replacement reference. For inline captures the mesh_<HASH> prototype holds the geometry and the inst_<HASH>_<N> prim owns the prepend references that makes it visible, which is why the instance carries the mask. A mesh_<HASH> path is still accepted for captures whose prototype references external geometry.

Export materials

  1. Select the mesh whose material you want to replace and open the Shader Editor
  2. Captured materials come in as Aperture node groups; Principled BSDF works too
  3. Use Create Aperture Opaque / Translucent from the Shader Editor sidebar when authoring a material from scratch
  4. Press Export Selected Materials

Exported assets

Exported Assets lists every mesh and light reference the selected layers author, with a select / delete action and a Show Assets Not in Scene filter.

Known issues

  • Skinned mesh export is not supported yet (no skeleton replacement / joint remapping)
  • Apply Mod File Changes is experimental and may behave unexpectedly
  • Light replacement is not wired to /RootNode/lights/light_<HASH> yet — lights exported without a target mesh end up under /RootNode/remix_assets
  • Albedo textures with an alpha channel may not round-trip correctly
  • Some .dds textures appear purple; use Captures > Fix Broken Textures
  • The Aperture Opaque node group is incomplete (animation, iridescence, flags, …)
  • Non-USD source assets (FBX/OBJ/glTF) are not ingested
  • Only one reference per mesh prim can be authored; combining assets into one mesh is not supported
