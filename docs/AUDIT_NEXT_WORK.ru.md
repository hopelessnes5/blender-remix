## Обязательные требования пользователя

1. Импорт и экспорт работают внутри Blender на его bundled `bpy`/`pxr`. Не устанавливай отдельный OpenUSD из pip, не вводи Toolkit/Kit/StageCraft/REST/MCP как обязательный runtime. Локальный Toolkit — эталон алгоритмов, а не запускаемая зависимость.
2. Capture-файлы и их исходные ресурсы не должны изменяться. Записываются только разрешённый mod/целевой replacement layer и подготовленные экспортные ассеты. Проверка должна действовать на всех путях записи, независимо от того, импортировали capture ранее или нет.
3. Превью захватов берутся прямо из папки captures/thumbs; файловая конвертация и кэш превью в каталоге плагина не возвращаются. Не меняй рабочее решение thumbnails ради других текстурных задач.
4. Имена экспортных текстур берутся из Image используемой ноды. Не возвращай автоматические `_Normal`, `_BaseColor`, `.n.rtex`, `.a.rtex` и hash/encoding-суффиксы. Конфликтующие имена разных данных выявляются до записи с понятной ошибкой; не разрешай конфликт тихой перезаписью.
5. Материальный override должен использовать исходный `mat_<HASH>`, например `/RootNode/Looks/mat_9BF7DE6807F288EC`, а не новый UUID вместо capture material hash. Учти, что такой override влияет на все использующие этот материал объекты.
6. Экспортировать только необходимые параметры относительно эффективной композиции/MDL defaults, но обязательно сохранять явные значения, нужные для перекрытия более слабого capture/mod. Нельзя ради компактности потерять пользовательское изменение.
7. Hide/restore относятся к `mesh_<HASH>` и всем его инстансам; не возвращай скрытие одного `inst_<HASH>_N`. Сохраняй replacement holders и не меняй capture.
8. Height export и Displacement: `Scale = displace_in + displace_out`, `Midlevel = displace_in / Scale`; обратное преобразование `displace_in = Scale*Midlevel`, `displace_out = Scale*(1-Midlevel)`. При Scale=0 оба displacement равны нулю, Midlevel может быть нейтральным 0.5. Не обещай равное физическое смещение Blender/Remix без проверки единиц runtime.
9. Сохрани UI `Export Settings > Normal Encoding` с режимами OCT_CONVERT, OCT_EXISTING, OPENGL, DIRECTX. Значения USD: octahedral=0, OpenGL=1, DirectX=2; соответствующий линейный DDS BC5/BC7. Сохрани прежний default OCT_CONVERT, если исследование не докажет необходимость изменения и не будет принято отдельное решение.
10. Обычная XY-карта с B=0 не определяется автоматически как octahedral. OCT_EXISTING предназначен только для действительно закодированных octahedral RG. Для конвертации используй алгоритм NVIDIA и сохраняй Apache/NVIDIA attribution.
11. Анализатор очистки суффиксов остаётся отдельным скриптом: анализ по умолчанию, запись только по явному флагу, проверяемый backup, защита capture/коллизий, безопасный откат. Не запускай cleanup на реальных пользовательских модах без соответствующего задания.
12. Не меняй Blender пользователя, не требуй переезда на другой путь установки и не объясняй ошибки предположениями о неверных действиях пользователя без доказательств.

Сначала проследи реальные пользовательские entry points и повторно проверь актуальность находок. Исправляй причины с учётом обоих экспортных путей (`operators/export_operator.py`, `export_utils.py`) и обоих путей применения/импорта материалов (`material_utils.py`, `mod_apply_utils.py`, `mod_loader.py`). Не оставляй второй путь с прежним дефектом.

Раздели архитектуру на подготовку данных, валидацию, создание файлов и фиксацию результата. Не выполняй тотальную перепись проекта. Введи общие структуры/функции там, где они устраняют реальное дублирование: разрешение активного shader graph, texture request с каналом/кодировкой, export plan с назначениями, безопасная запись USD, преобразования единиц.

Работай в существующем подходящем checkout; не создавай новую ветку/worktree без необходимости. Не делай commit, push, release, установку сборки в пользовательский Blender или изменение реального мода автоматически. Изменения должны быть готовы к проверке локально. Если окружение ограничивает запись в F:, подготовь и протестируй изменения в разрешённой копии, затем перенеси только нужные файлы с проверкой исходных хэшей и необходимым системным разрешением.

## Этап 1. Безопасная запись и корректное завершение экспорта

Закрой A01–A05, A14 и затрагиваемую часть A26.

- Создай единый guard для writer entry points: слой не capture, разрешён к редактированию, относится к выбранному проекту/целевому выходу. Экспорт, удаление ассетов, create/add sublayer не обходят проверку. Прямой вызов низкоуровневого экспортёра тоже должен быть защищён на разумной границе.
- До изменения USD собери план выходных файлов, ролей, каналов и кодировок для всей операции. Найди коллизии между материалами, существующими файлами и исходниками. Нормализуй пути правильно для Windows.
- Защити источник нормали так же тщательно, как height source. Проверяй actual source/destination, а не только имена. Не добавляй суффиксы для обхода конфликта.
- Все обращения к Blender datablocks, pixels, nodes, scene и settings выполняй в main thread. В фон допускаются texconv/subprocess и обработка уже подготовленных независимых данных. Не передавай bpy Image/Scene в worker.
- Подготовь атомарную фиксацию на уровне одного экспортируемого элемента: временные ассеты/staging layer, валидация, затем публикация. Для многофайловой операции явно определи rollback; не называй Sdf.ChangeBlock транзакцией.
- DDS failure/timeout/cancel не должны считаться успехом. Нельзя записать новую ссылку в USD, сообщить FINISHED и позже выяснить, что файл не появился. Сохрани отзывчивость UI через modal/timer, если работа длительная.
- При disable/reload/load нового .blend безопасно останови jobs, снимай таймеры, не применяй callbacks к удалённым datablocks, прибирай собственные временные файлы.

Приёмка: байты capture и source textures неизменны; принудительная ошибка любого шага не меняет прежний успешный результат данного элемента; разные материалы не могут молча записать разные данные в один путь; worker не обращается к bpy; статус пользователя соответствует реальному результату.

## Этап 2. Согласованное состояние материала и текстуры

Закрой A06–A13, A24 и общий анализатор из A08/A10.

- Определяй shader от активного Material Output.Surface. Отключённые nodes не участвуют. Договорись о поддерживаемых reroutes/legacy groups. Неподдерживаемый Mix/граф выдаёт понятный отказ либо проходит отдельный поддерживаемый bake.
- Генерируй желаемый набор управляемых USD inputs и согласовывай с текущим слоем и более слабой композицией. Повторный экспорт должен удалять/блокировать устаревшие normal/height/opacity/emission/specular мнения; при необходимости явно выключать функции capture. Чужие свойства не трогай.
- Решай omission MDL defaults в полной композиции. Проверка: capture roughness=0.8, Blender=0.5, отдельный сильный replacement layer — итог ровно 0.5. Повтори для bool/color/displacement defaults.
- Проверь переключение opaque/translucent: актуальная MDL-семья, подключения и inputs должны соответствовать новому графу и корректно перекрывать исходный материал.
- Для каждой текстуры сохраняй выбранный output channel. Grayscale roughness/metallic BC4 не подключаются к alpha=1; отдельная opacity из Alpha экспортирует Alpha, а не R. Для Scalar Color определись с преобразованием Color→Value и проверь его численно. Не применяй display/view transform к данным normal/height/roughness/metallic.
- Для Normal Map читай encoding из USD, сохрани provenance и создавай корректное Blender-представление. Исключи двойную octahedral conversion. Проверяй OpenGL/DirectX Y convention, а не только наличие B=0. Сохрани настройку default экспорта и документируй применение к imported и новым изображениям.
- DDS fallback должен переживать сохранение/открытие .blend и reload. Упакуй временно декодированное изображение или создай устойчивый источник, не возвращая удаляемый temp path.
- При повторном экспорте реально изменённые изображения пересоздают DDS. Если нужен reuse, доказывай идентичность source+pixels+conversion settings; одно существование файла недостаточно.
- Dedup объединяет только доказанно одинаковые изображения с одинаковой интерпретацией. Разные pixels/paths/colorspaces/dirty data не объединяются. Не обращайся к Image после удаления.

Приёмка: численное соответствие каналов после реального DDS decode; корректный второй экспорт после отключения каждой карты; нормали сохраняют направления в цикле import/export; .blend reopen не теряет изображения; отключённый BSDF с roughness=0.1 и активный=0.9 дают экспорт 0.9.

## Этап 3. Геометрия и материалы инстансов

Закрой A15–A20 и A28.

- Приведи counts/indices/face offsets к одной модели при удалении вырожденных граней. Сохрани правильное соответствие topology, UV, normals и material subsets.
- Обрабатывай indexed primvars для всех поддерживаемых interpolation (vertex/varying/uniform/constant/faceVarying), с проверкой диапазонов.
- Поддержи стандартный `UsdGeom.Mesh.normals` и capture `primvars:normals`, сохрани interpolation/custom normals.
- Импортируй собственную вложенную структуру `ref_.../XForms/Mesh` и несколько Mesh под prototype, учитывая их локальные transform. Не выбирай только первый случайный Mesh. Сохрани совместное использование geometry datablocks и provenance для hide/export.
- Сохрани materialBind GeomSubset ↔ polygon.material_index ↔ slots при импорте/экспорте либо явно откажи в многоматериальном экспорте до записи, пока поддержка не реализована.

- Сбор capture hashes не падает на пустом relationship, prepend-only или отсутствующем материале; mesh hash сохраняется.

Приёмка: topology [2,3]/[0,1,2,3,4] даёт оставшуюся грань [2,3,4]; UV и normals совпадают по corners; собственный экспортированный мод открывается direct backend с теми же мешами и transform; два инстанса одного Mesh сохраняют независимые материалы.

## Этап 4. Единицы света и камера
