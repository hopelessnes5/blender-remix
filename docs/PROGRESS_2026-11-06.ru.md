# Прогресс разработки Blender Remix на 6 ноября 2026

## Сфера документа и статус проверки

Исходная версия установленного аддона по `rtx_remix_importer/__init__.py`: **0.5.0**. Источник базовой кодовой базы — переданный пользователем `blender-remix(1).zip`, а также последовательность локальных ZIP-патчей в разговоре. Ветка исходного аудита и старые значения badges не доказывают, что последняя комбинация патчей работает в установленном Blender.

Эта сводка отделяет **обнаруженное в исходниках** от **сообщений о результате**. Положительно подтверждено пользователем: RG-нода нормалей работает. Пользователь отдельно сообщил о невидимом меше и потере UV после применения мода; подготовлен защитный патч, но его результат в Blender пока не подтверждён. Пользователь также сообщил реальный traceback `ModuleNotFoundError: No module named 'rtx_remix_importer.material_family'` при `Apply Mod File Changes`.

## Текущая ошибка выполнения (P0 — упаковка/зависимости)

При выполнении `rtx_remix_importer/ui/operators/sync_ops.py` через `_update_material_only()` в `mod_loader.py` вызывается `create_mod_material_nodes_util()` в `mod_apply_utils.py`. Код выполняет `from .material_family import detect_nvidia_shader_family`, но в папке установленного аддона отсутствует `material_family.py`. В локальной исходной копии модуль есть, а в `Blender_Remix_Mesh_Visibility_UV_Preservation_Fix.zip` его нет. Ошибка возникает **до применения** материала, поэтому это не дефект Classifier API и не подтверждение сбоя Blender nodes.

Исправление: поместить `rtx_remix_importer/material_family.py` из `Blender_Remix_Missing_Material_Family_Fix.zip` в `Blender/4.5/scripts/addons/rtx_remix_importer/`, перезапустить Blender и повторить применение мода. Не удалять `subsurface`-исправление из вызывающего кода: оно устраняет ошибочную классификацию непрозрачного растительного материала как Glass.

## Что проверить в первую очередь

1. **Комплектность установки:** единое дерево исходников, `material_family.py` физически находится рядом с `mod_apply_utils.py`; проверить относительные импорты и содержимое дистрибутивного ZIP, не только отдельных patch ZIP.
2. **Перезапуск Blender 4.5:** `Apply Mod File Changes` для материала с `subsurface_*` не падает; создаёт Principled, а настоящий `AperturePBR_Translucent` — Glass.
3. **Light-only mesh prototype:** импорт мода с nested light не скрывает Mesh во viewport/render; ранее скрытые объекты не заменяются пустой геометрией.
4. **UV:** импорт capture и повторное применение мода сохраняют UV на неизменённой топологии; для другой топологии без UV операция должна завершаться безопасным отказом.
5. **Instance light sharing:** одинаковые источники из одного prototype используют общий Light datablock, но расположены согласно матрицам своих экземпляров; индивидуальные USD overrides не сливаются.
6. **Семантика света:** `SphereLight` с конусными атрибутами — SPOT, без них — POINT; `DistantLight` — SUN, сверить angle и Y-up rotation.
7. **Повторный запуск:** применять мод дважды без накопления дубликатов света, мешей, node groups и потери пользовательских изменений.
8. **Тесты:** прогнать `tests/run_tests.py` в Blender 4.5 и, если доступен, 5.1; учесть fail/skip. Не обновлять badges и официальные проценты по числу тестов из старого README.

## Вне текущей проверки

Работа без RTX Remix Toolkit (прямая интеграция через `pxr`), отсутствие REST/MCP, необратимые/ограниченные отличия NVIDIA MDL и Blender BSDF. В данном окружении проверены семь unit-тестов `tests/unit/test_material_family.py` и Python compileall трёх связанных модулей; **не запускались** фактический GUI Blender, полная сцена захвата, игровой RTX Remix runtime и настоящий интеграционный suite новой совокупности патчей.

## Дополнение: SKY-меши и SUN (6 ноября 2026)

### Пользовательский отчёт

При применении мода были пропущены светильники:

```text
No capture instance for prototype light /RootNode/meshes/mesh_5E68DDDA519FEA31/light_17d87578; skipping
No capture instance for prototype light /RootNode/meshes/mesh_5E68DDDA519FEA31/light_bf922cef; skipping
```

Пользователь уточнил, что геометрия неба при импорте именуется **`sky_<HASH>`**, а не `mesh_<HASH>`. Из-за этого сопоставление исключительно по `inst_<HASH>_*` и USD instance tags недостаточно: sky-объект может существовать в Blender без `usd_instance_path`, тогда как мод добавляет свет под USD-прототипом `/RootNode/meshes/mesh_<HASH>`.

### Реализация локального патча

`Blender_Remix_Sky_Sun_Import_Fix.zip` содержит:

- `rtx_remix_importer/ui/operators/mod_loader.py` — строгая идентификация `sky_<16 hex>` у объектов/мешей Blender, связывание его hash с USD-прототипом `mesh_<HASH>` или `sky_<HASH>`; резервный импорт `DistantLight` без capture instance; обработка прямых `light_*` и светильников внутри `ref_*`.
- `tests/unit/test_sky_sun_routing.py` — распознавание sky-имён, проверка hash и поиска USD-контейнера.
- `tests/unit/test_mod_light_instancing_mock.py` — один SUN для sky без instance; повторная привязка общих datablock света и сохранение индивидуальных overrides.
- `tests/blender/test_mod_sky_sun.py` — интеграционная проверка на настоящих `bpy + pxr` для двух SUN, UV sky и повторного Apply; здесь не выполнялась.

Для неба без экземпляров сцены источник `DistantLight` может быть представлен отдельным Blender SUN без искусственного Mesh-якоря. Это специальная обработка **направленного света** и не универсальный способ размещения обычных `SphereLight`, `RectLight` и других привязанных источников. Если в составной сцене существуют реальные экземпляры, они имеют приоритет; направление и трансформации следует проверять отдельно.

### Проверки и незакрытые вопросы

- 8/8 автономных unit-тестов пройдены при проверке с `light_sharing.py` из предыдущего патча. Это тесты логики без реальных `bpy` и `pxr`.
- Не выполнялся интеграционный тест `tests/blender/test_mod_sky_sun.py` на Blender 4.5 с реальными захватами.
- Не подтверждено пользователем, что оба `light_17d87578` и `light_bf922cef` появились на реальной сцене и верно ориентированы.
- Проверить отсутствие дубликатов при повторном `Apply Mod File Changes`, UV/видимость `sky_5E68DDDA519FEA31`, а также отсутствие записи в исходные `.usd/.usda`.
- Патч **инкрементальный**: для его запуска должны сохраняться зависимости предыдущих исправлений (в частности `light_sharing.py`, `mesh_uv_preservation.py`, `material_family.py`). Не заменять им весь пакет целиком без этих файлов.
